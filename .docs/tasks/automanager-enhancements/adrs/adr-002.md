# ADR-002: Module Structure — Flat Files in Project Root

**Date:** 2026-05-19  
**Status:** Accepted  
**Context:** The monolithic `llama_manager.py` (2408 lines) must be refactored into dedicated modules. The question was how to organize these modules: nested package, flat files with namespace prefix, or flat files alongside the entry point.  
**Decision:** Use flat Python modules in the project root alongside `llama_manager.py`: `gpu_manager.py`, `log_manager.py`, `ui_renderer.py`, `process_manager.py`, `config_manager.py`. The entry point `llama_manager.py` imports from these modules and contains only API routes and FastAPI app setup.  
**Alternatives Considered:**
- **Nested package (`automanager/`):** Better namespace isolation but requires `__init__.py` management, changes import paths throughout, and adds a directory level that complicates single-file debugging.
- **Prefixed flat files (`am_gpu.py`):** Avoids naming conflicts but creates noisy prefixes and doesn't scale well if modules grow into sub-packages.
**Consequences:**
- Simplest import structure: `from gpu_manager import GPUDetector`
- Easy to find and edit individual modules
- No package overhead for a small project
- Risk of namespace collisions if module names conflict with stdlib (mitigated by using descriptive names like `log_manager`)
- Scales well up to ~10 modules before needing a package structure
