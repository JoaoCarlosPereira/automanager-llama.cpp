# ADR-001: Modular Refactoring Strategy

**Date:** 2026-05-19  
**Status:** Accepted  
**Context:** O `llama_manager.py` é um arquivo monolítico de ~2400 linhas combinando lógica de GPU, logs, UI, configuração e processo management. As melhorias solicitadas (GPU strict enforcement, log files, UI components, quick-install) exigem mudanças em múltiplas áreas interdependentes.  
**Decision:** Adotar refatoração modular progressiva — separar o monolito em módulos dedicados antes de implementar as features.  
**Alternatives Considered:**
- **Iterativa por Sprints:** Implementar cada feature independentemente no monolito. Risco menor por sprint, mas maior tempo total e risco de merge conflicts.
- **Big-Bang Coordinated:** Implementar tudo em uma única mudança atômica. Risco alto de quebrar integrações, PR enorme difícil de revisar.
**Consequences:**
- Código mais organizável, testável e com menor acoplamento
- Cada módulo pode ser modificado independentemente
- Facilita implementação de cada feature em seu domínio
- Maior esforço inicial de refatoração
- Risco moderado de quebrar integrações durante a separação (mitigado por testes)
- Facilita onboarding de novos desenvolvedores
