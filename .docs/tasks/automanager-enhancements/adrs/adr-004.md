# ADR-004: Log Rotation — Hybrid Handler Approach

**Date:** 2026-05-19  
**Status:** Accepted  
**Context:** Current logging uses `logging.basicConfig()` with a single file handler writing to `/root/manager.log`. Server logs are redirected via `open(SERVER_LOG_PATH, "a")`. No rotation exists — files grow unbounded. We need log rotation to project-local `logs/` directory while maintaining backward compatibility with existing system paths.  
**Decision:** Keep the existing `basicConfig()` call unchanged (preserves all existing code behavior) and add a `RotatingFileHandler` to the same `"automanager"` logger that writes to `logs/manager.log` with 10MB max size and 3 backup files. For server logs, redirect `llama-server` stdout to `logs/server.log` instead of `/root/llama_server.log`. The SSE stream continues reading from the project-local file.  
**Alternatives Considered:**
- **Wrapper LogService:** Create an abstraction layer that replaces all `logger.info()` calls. Requires changing every logging call in the codebase — high risk of breaking existing behavior.
- **Dual handler only:** Add both handlers via `basicConfig(handlers=[])`. Less flexible for future rotation config changes.
**Consequences:**
- Zero code changes needed for existing `logger.info()` / `logger.error()` calls
- Log rotation is automatic and transparent
- Project-local logs are accessible via file system without SSH to `/root/`
- Backward compatible: system log paths still receive output
- Dual-write ensures no log loss during migration
- SSE stream reads from project-local path (no change to existing behavior)
- Server log path constant `SERVER_LOG_PATH` must be updated to project-local path
