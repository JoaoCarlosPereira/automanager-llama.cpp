# ADR-003: GPU Strict Enforcement via CUDA_VISIBLE_DEVICES

**Date:** 2026-05-19  
**Status:** Accepted  
**Context:** Currently, `ProcessManager.start()` builds a `--tensor-split` array for ALL detected GPUs (indices 0 through max_idx). GPUs marked `active=False` or with `weight=0` receive a split value of `0.0000`, but llama.cpp can still enumerate them. We need to guarantee that disabled GPUs are completely invisible to the llama-server process.  
**Decision:** Set the `CUDA_VISIBLE_DEVICES` environment variable to only the indices of GPUs with `active=True` and `weight > 0`. Simultaneously, recompute the `--tensor-split` array to contain ONLY the active GPUs, normalizing weights proportionally among remaining active GPUs.  
**Example:**  
- Before: GPU 0 (active, weight 80), GPU 1 (active, weight 20) → split `"0.8000,0.2000"`  
- User disables GPU 0 → GPU 1 (active, weight 20) → CUDA_VISIBLE_DEVICES=`1`, split `"1.0000"`  
- User disables GPU 1 → GPU 0 (active, weight 80) → CUDA_VISIBLE_DEVICES=`0`, split `"1.0000"`  
**Alternatives Considered:**
- **Filter-only (no CUDA_VISIBLE_DEVICES):** Remove inactive GPUs from split array but don't set CUDA_VISIBLE_DEVICES. llama.cpp might still enumerate disabled GPUs through driver-level APIs.
- **Proportional with minimum:** Normalize with a 50% minimum per GPU. Adds complexity for marginal benefit.
**Consequences:**
- GPU isolation is guaranteed at the OS driver level (CUDA runtime respects CUDA_VISIBLE_DEVICES)
- Tensor split is always clean (N values for N visible GPUs)
- Proportional weight recomputation prevents user from accidentally leaving broken weights
- If all GPUs are disabled, start is rejected with a clear error message
- Backward compatible: existing active GPU selections produce identical behavior
