# ADR-001: Extração de JavaScript para testes unitários com Jest + Playwright E2E

> **Idioma:** escreva todo o conteúdo deste arquivo em **português brasileiro (PT-BR)**.

## Status

Aceito

## Data

2026-06-02

## Contexto

O projeto `automanager-llama.cpp` possui uma dashboard SPA gerada via f-string Python no arquivo `llama_manager.py` (linhas 969-2100+). O JavaScript é 100% embutido no HTML, impossibilitando testes unitários isolados das funções. Os testes existentes cobrem apenas o backend (API com `httpx TestClient`). O objetivo é garantir que alterações futuras não quebrem a interface, cobrindo login, carregamento da página, presença de componentes e interações do usuário.

## Decisão

Extrair todo o JavaScript embutido do HTML para arquivos `.js` separados na pasta `static/js/`, e adotar Jest para testes unitários de cada função JS + Playwright para testes E2E de interações reais no navegador.

## Alternativas Consideradas

### Alternativa 1: HTML Contract via Python + Playwright E2E

- **Descrição**: Manter o JS embutido e validar presença de elementos HTML via Python, complementar com Playwright para interações
- **Prós**: Sem necessidade de extração de JS, mantém estrutura atual
- **Contras**: Menor granularidade nos testes, não testa funções isoladamente, difícil testar lógica complexa
- **Por que rejeitada**: Não atende ao requisito de testar funções JS unitariamente para garantir que nenhuma lógica se degrade

### Alternativa 2: Híbrida — Extrair só o crítico + Playwright

- **Descrição**: Extrair apenas as funções JS mais complexas para testes, manter as demais no HTML
- **Prós**: Menor esforço de refatoração
- **Contras**: Cobertura desigual, lacunas em funções menores não extraídas
- **Por que rejeitada**: O usuário solicitou cobertura de todas as funções, não apenas as críticas

### Alternativa 3: Extração completa + Jest + Playwright (Escolhida)

- **Descrição**: Extrair todo o JS para arquivos separados, testar com Jest + Playwright
- **Prós**: Cobertura completa, testes rápidos e isolados, padrão da indústria, fácil expandir
- **Contras**: Requer refactor do `llama_manager.py`, mais arquivos para manter
- **Por que escolhida**: Atende totalmente ao requisito do usuário de testar todas as funções e garantir segurança contra regressões

## Consequências

### Positivas

- Testes unitários rápidos e isolados — não requerem navegador
- Cobertura de todas as funções JS — autenticação, gerenciamento de modelos, métricas, GPU/auto-balance
- Playwright valida interações reais do usuário no navegador
- Fácil adicionar novos testes conforme o projeto evolui
- Jest é o padrão da indústria — qualquer desenvolvedor consegue contribuir

### Negativas

- Necessidade de refactor do `llama_manager.py` para servir arquivos JS externos ao invés de embutidos
- Mais arquivos para manter na estrutura do projeto
- Configuração adicional (Jest, Playwright) no ambiente de desenvolvimento

### Riscos

- **Risco**: Breakage na extração se alguma função JS depender de variáveis do escopo HTML
  **Mitigação**: Refatoração incremental, rodar suite de testes após cada módulo extraído
- **Risco**: Playwright testes podem ser lentos ou flaky
  **Mitigação**: Usar condicion-based waits, rodar em paralelo com Jest, limitar Playwright aos fluxos de interação

## Notas de Implementação

1. Mover o JS embutido de `llama_manager.py` para `static/js/app.js`
2. Atualizar `_build_html()` para referenciar o arquivo via `<script src="/static/js/app.js"></script>`
3. Criar `jest.config.js` e `static/js/app.test.js`
4. Criar `playwright.config.ts` e `tests/e2e/`
5. Adicionar `jest`, `@playwright/test` ao `requirements.txt` (via `playwright` para Python, Jest via npm)
6. Manter a estrutura `tests/` existente — adicionar `tests/e2e/` para Playwright
