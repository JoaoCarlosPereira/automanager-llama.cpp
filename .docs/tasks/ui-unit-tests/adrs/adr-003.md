# ADR-003: Estratégia de mock para testes E2E com Playwright

> **Idioma:** escreva todo o conteúdo deste arquivo em **português brasileiro (PT-BR)**.

## Status

Aceito

## Data

2026-06-02

## Contexto

Os testes E2E com Playwright interagem com a aplicação FastAPI rodando em um navegador real. Sem mock, os testes dependem de: servidor GPU disponível, llama-server instalado, arquivos de modelo .gguf no sistema de arquivos, e estado consistente do backend. Isso torna os testes E2E lentos, frágeis e dependentes de infraestrutura.

## Decisão

Mockar **todas** as respostas da API via FastAPI `dependency_overrides` dentro de um servidor FastAPI dedicado para testes E2E. Este servidor mock substitui toda a lógica de backend por respostas determinísticas controladas pelos testes:

- `GET /status` → retorna `{ running: true, model: "test-model.gguf", ... }`
- `GET /metrics` → retorna métricas fake com valores controlados
- `GET /models` → retorna lista de modelos fake pré-definida
- `POST /api/auth/login` → retorna cookie de sessão válido para qualquer credencial
- `POST /start` → retorna `{ probing: false, ... }`
- `POST /stop` → retorna `{ status: "ok" }`
- `POST /rename`, `POST /delete` → retornam `{ ok: true }`
- `GET /logs` → retorna SSE stream fake com linhas controladas
- `GET /downloads` → retorna `{}`
- `POST /downloads` → retorna `{ ok: true }`

O Playwright aponta para este servidor mock via `baseURL`, e cada teste pode modificar o estado do mock antes da interação.

## Alternativas Consideradas

### Alternativa 1: Playwright + FastAPI TestServer com dependency overrides (Escolhida)

- **Descrição**: Playwright conecta a um servidor FastAPI rodando localmente com todos os endpoints mockados
- **Prós**: JS real roda no navegador, testes isolam UI sem depender de GPU/backend, rápido, determinístico
- **Contras**: Requer manutenção de um conjunto de mocks, não valida integração real com backend
- **Por que escolhida**: O PRD foca em proteger a UI de regressões, não em testar integração com backend. Testes de API já existem via `httpx TestClient`

### Alternativa 2: Playwright + backend real com GPU

- **Descrição**: Rodar testes E2E contra o backend real com GPU disponível
- **Prós**: Testes mais fiéis ao comportamento real
- **Contras**: Requer hardware GPU, testes lentos (start/stop real de llama-server), dependência de modelos .gguf, alta probabilidade de flakiness
- **Por que rejeitada**: inviável para desenvolvimento local, muito lento para execução frequente

### Alternativa 3: Playwright + mock seletivo (apenas autenticação e métricas)

- **Descrição**: Mockar apenas autenticação e métricas, mas deixar start/stop e models com backend real
- **Prós**: Combina realismo com isolamento
- **Contras**: Estado inconsistente entre mock e real, complexidade de manter dois modos de operação, ainda depende de GPU para start/stop
- **Por que rejeitada**: O PRD solicitou mock total (opção A nas perguntas técnicas) para isolar completamente testes de UI

## Consequências

### Positivas

- Testes E2E rodam em qualquer máquina — sem necessidade de GPU
- Execução determinística — mesmo resultado a cada execução
- Rápido — sem tempo de startup do llama-server
- Isolamento total — bugs no backend não causam falhas nos testes de UI
- Fácil de adicionar cenários de erro — basta modificar a resposta do mock

### Negativas

- Testes E2E não detectam regressões na integração backend-frontend (mas isso é coberto por `httpx TestClient`)
- Se o backend mudar a estrutura de resposta sem atualizar o mock, o mock pode mascarar o erro
- Manutenção adicional: cada novo endpoint precisa de um mock correspondente

### Riscos

- **Risco**: Mock desatualizado — novos endpoints do backend não têm mock correspondente
  **Mitigação**: Incluir no checklist de desenvolvimento: "adicionar mock para novo endpoint"
- **Risco**: Mock não cobre todos os cenários de erro que o backend real produz
  **Mitigação**: Revisar mocks periodicamente contra o backend real, especialmente após mudanças de API

## Notas de Implementação

Estrutura do servidor mock:

```python
# tests/e2e/conftest.py

from fastapi.testclient import TestClient
from llama_manager import app
from llama_manager import auth_manager

@pytest.fixture
def mock_app():
    """FastAPI app com dependency overrides para E2E testing."""
    def fake_auth():
        return {"sub": "admin", "role": "admin"}
    def fake_status():
        return {"running": False, "model": None}
    
    app.dependency_overrides = {
        auth_manager.get_current_user: fake_auth,
        # ... mais overrides
    }
    yield app
    app.dependency_overrides.clear()
```

Playwright config (`playwright.config.ts`):
```typescript
export default defineConfig({
    testDir: './tests/e2e',
    use: {
        baseURL: 'http://127.0.0.1:8001',
        trace: 'on-first-retry',
        screenshot: 'only-on-failure',
    },
    webServer: {
        command: 'python -m tests.e2e.mock_server',
        url: 'http://127.0.0.1:8001/',
        reuseExistingServer: !process.env.CI,
    },
    projects: [{ name: 'chromium', use: { browserName: 'chromium' } }],
});
```
