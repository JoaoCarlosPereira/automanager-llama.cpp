# ADR-001: CPU como Dispositivo Unificado na Tabela de Recursos

**Data**: 2026-06-07  
**Status**: Aceito  
**Autor**: Cy Create PRD  

## Contexto

O Automanager atualmente exibe uma tabela "Recursos de GPU & Configuração" com linhas para cada GPU detectada. O usuário deseja estender esta tabela para incluir a CPU como um dispositivo adicional de compute, permitindo offload quando o VRAM total for insuficiente.

## Decisão

A CPU aparecerá como mais uma linha na tabela unificada "Recursos de GPU & Configuração", seguindo exatamente o mesmo padrão visual das GPUs:

- **Nome**: Nome completo do processador (ex: "Intel Xeon E5-2680 v4")
- **Coluna Monitoramento**: CPU usage % com barra de progresso
- **Coluna RAM**: RAM usada / RAM total em MB com barra de progresso
- **Coluna Distribuição**: Input numérico de peso % com checkbox
- **Peso**: CPU e GPUs compartilham 100% juntos

## Alternativas Consideradas

### Abordagem 1: CPU como Dispositivo Unificado (Escolhida)
Mesma tabela, mesmo padrão visual.

**Vantagens**:
- Consistência visual total
- Experiência unificada e intuitiva
- O usuário entende que CPU é um "dispositivo" adicional de compute
- Mais fácil de implementar (apenas estende a tabela existente)

**Desvantagens**:
- Semânticamente a CPU não é um dispositivo tensor split como GPUs

### Abordagem 2: Seção Híbrida
GPUs na tabela principal, CPU em seção separada abaixo.

**Vantagens**:
- Clarifica diferença técnica entre CPU e GPUs

**Desvantagens**:
- Quebra consistência visual
- Mais complexa de implementar
- Menos intuitiva

### Abordagem 3: Auto-Detect com Controle Manual
CPU aparece automaticamente quando VRAM insuficiente.

**Vantagens**:
- Menos clutter visual quando não necessário

**Desvantagens**:
- Adiciona lógica de decisão complexa
- Menos controle ao usuário

## Consequências

- O usuário terá uma experiência visual consistente e intuitiva
- A implementação precisará adaptar o backend: CPU usa `--n-gpu-layers` em vez de tensor split
- O auto balance precisará ser estendido para incluir a CPU no cálculo
- A detecção do processador requer parsing de `/proc/cpuinfo` (Linux) ou registry (Windows)
